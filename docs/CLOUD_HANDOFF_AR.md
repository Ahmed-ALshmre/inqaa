## ما يريده المالك من الرد والحجز

1. رد عراقي مختصر وطبيعي، يجيب على السؤال نفسه. التحية في بداية المحادثة، دون إعادة الترحيب أو اسم الموديل أو قائمة المواصفات في كل دور.
2. استعمل الفئة التي أدخلها الموظف مثل قميص، تنورة، بنطرون، دشداشة عند الحاجة. الأسماء الداخلية مثل «تراك ولادي تطعيم» ليست قالباً لكل رد.
3. تذكّر اختيار اللون والقياس والعمر والكمية والمنتج وأحدث تصحيح. لا تنقل قياس موديل إلى آخر، ولا تحول الوزن إلى مقاس جديد بعد اختيار مقاس صريح. لا تُعد سؤال معلومة وصلت سابقاً.
   الأحذية تعتمد قياس القدم المتوفر، دون تحويل عمر الطفل أو الوزن إلى قياس حذاء. الحقيبة ذات `size_system=none` لا تحتاج سؤال قياس أو وزن قبل الحجز؛ أبعادها تؤخذ من بياناتها عند السؤال عنها.
4. اطلب أقرب معلومة ناقصة فقط. إذا اكتمل اختيار الشراء، اطلب الرقم والعنوان باختصار. إذا وصل الرقم فاطلب العنوان فقط؛ وإذا وصل العنوان فاطلب الرقم فقط.
5. عند اكتمال اختيار الشراء والرقم والعنوان، يُحفظ الطلب فوراً إذا اجتاز شروط صحة السلة، ثم يُرسل التأكيد بعد نجاح الحفظ. الاستفسار عن سعر قطعتين ليس شراءً. لا تؤكد حفظاً لم يحصل، ولا تنشئ طلباً مكرراً عند إعادة إرسال التأكيد.
   نص التأكيد الافتراضي الذي اعتمده المالك في 5 نوفمبر: «تم تثبيت الطلب. يرجى فحص الطلب بحضور المندوب والتأكد من الموديل والقياس. إذا لم يطابق الطلب يرجع مع المندوب بدون دفع. أهم شي فحص الطلب قبل دفع المبلغ.» لا تختصره إلى «تم تثبيت الطلب عيوني». يظل نص المتجر المخصص قابلاً للتعديل من إعداداته.
6. استخدم سعر وعرض وتوصيل المنتج والمتجر الحاليين. لا تعمم عرض قطعتين بــ20 ألف أو توصيل 5 آلاف على كل منتج مستقبلياً؛ هذه أمثلة لها بيانات. تجنب تكرار «عرض قطعتين» مرتين من حقول الكتالوج.
7. تفاوض السعر سؤال بيع عادي؛ اشرح العرض أو السعر المعتمد بسلاسة، ثم أكمل الاختيار. لا تختلق تخفيضاً أو ندرة أو نهاية عرض أو خواص قماش غير مسجلة.
8. أرسل صور الألوان المتاحة فعلاً عند الحاجة، ثم سؤال الاختيار المناسب. لا تدّع إرسال صورة أو فيديو غير موجود. اللون القريب اقتراح يحتاج موافقة، وليس بديلاً صامتاً عن اختيار الزبون.
9. تُقسم الردود الطويلة حسب المعنى وتسلسل الصور. تأكيد حفظ الطلب يبقى متماسكاً. لا تكرر السؤال أو تحصر الردود في جمل جامدة.
10. في الملابس النسائية استعمل المخاطبة المناسبة للسياق مع احترام تصريح الزبون. افصل جنس المشتري عن الطفل أو الشخص المقصود بالشراء.
11. المعلومة الناقصة فعلاً تتحول إلى مراجعة بشرية صامتة وسؤال في `/product-questions`؛ لا تُرسل «البيانات غير واضحة» للزبون، ولا تُخترع إجابة. معاينة الموظف تُظهر الحقل الناقص بوضوح دون تكرار المراجعة.
12. الشكاوى وإلغاء/تغيير الطلب والمتابعة الخاصة بالشحن تحتاج إجراءً مسجلاً وصلاحية مناسبة. لا تزعم تنفيذ الإلغاء أو وصول الشحنة لمجرد صياغة رد. لا تُغلق مراجعة معلقة لها إجراء طلب أو لون يحتاج مراجعة دون حل سببها.

الحقائق مثل الطول والخامة تؤخذ من المنتج نفسه، لا من مثال عام في دفتر الردود. الصياغات السابقة أمثلة للأسلوب وليست حقائق تجارية ثابتة أو أوامر لنسخ نفس النص في كل حالة.

## قراءة الإنتاج من Cloud

تحتاج بيئة Cloud إلى اتصال منفصل؛ ملف Windows DPAPI مرتبط بجهاز المالك ولا ينتقل إلى Cloud. اسم السر `INQAA_LIVE_TOKEN`. يفضل HTTP/Network secret بوجهة HTTPS الوحيدة `inqaa-production.up.railway.app`، داخل بيئة خاصة بالمالك. يستعمل العميل القيمة أو العنصر البديل الذي يقدمه وكيل الشبكة دون طباعته أو حفظه.

```bash
python -X utf8 tools/check_cloud_handoff.py --live
python -X utf8 tools/live_system.py manifest
python -X utf8 tools/live_system.py inbox --limit 100
python -X utf8 tools/live_system.py read conversations --store-id khuyoot --q "اسم الزبون"
python -X utf8 tools/live_system.py --output outputs/customer-review.json conversation "معرف المحادثة الكامل"
python -X utf8 tools/live_system.py products --store-id baraah-kids
python -X utf8 tools/live_system.py settings --store-id baraah-kids
python -X utf8 tools/live_system.py read jobs --sender-id "معرف المحادثة الكامل" --order desc
```

ابدأ بالـmanifest ثم اتبع الصفحات. `inbox` مرتب بآخر نشاط ويعيد `has_more`؛ التالي يستخدم `cursor_time` و`cursor_sender` من آخر صف. مجموعة `conversations` الخام مرتبة بمعرف إنشاء السجل، فلا تستعملها لادعاء قراءة أحدث 100 محادثة. `conversation` يجلب تاريخ الرسائل والحالات والطلبات ذات الصلة حتى نهاية الصفحات المحدودة بالحد الأعلى.

واجهة القراءة تُظهر 26 مورداً تشغيلياً، إضافة إلى المتاجر والمنتجات والإعدادات والكتالوج والمرفقات المحفوظة. لا تُظهر أسرار الخدمات أو ملفات الخادم الاعتباطية أو كلمات مرور الموظفين، ولا تسمح بإرسال رسائل أو تغيير الحالة. سياسة القراءة الحية ليست نسخة متسقة من قاعدة البيانات في لحظة واحدة؛ قد تتعدل السجلات أثناء جلب الصفحات. اذكر حدود العينة التي قرأتها.

## إعداد بيئة Cloud

1. اربط `Ahmed-ALshmre/inqaa` على `main` ببيئة `inqaa`، واحتفظ بخصوصيتها `Only me`.
2. سكربت تثبيت الأدوات: `bash tools/setup_codex_cloud.sh`. هذا السكربت يثبت الاعتماديات ويفحص وجود ملفات التسليم؛ لا يحتوي مفتاحاً ولا يشغّل خادم الإنتاج.
3. أضف HTTP secret باسم `INQAA_LIVE_TOKEN` بوجهة `inqaa-production.up.railway.app` وقيمة اتصال Cloud المخصص. لا تضع المفتاح داخل الوصف أو الرسائل أو Start skill أو Git أو سكربت التثبيت.
4. لا تحتاج وصولاً عاماً لكل الإنترنت لقراءة النظام؛ تكفي الوجهة المصرح بها. اسمح بمجالات مدير الحزم للتثبيت. ربط المستودع وصلاحيات Git منفصلان عن صلاحية API الحي.
5. Start skill المقترح: اقرأ `AGENTS.md` وملف التسليم هذا، افحص `git status` والإصدار، تحقق من الاتصال بـ`tools/check_cloud_handoff.py --live` دون طباعة الأسرار، ثم نفّذ مهمة المستخدم على فرع `codex/` مع اختبارات معزولة.
6. احفظ وانشر/أعد نشر البيئة. وجودها بحالة `Unpublished` أو `runnable=false` لا يكفي للعمل من الموبايل. اختبر الـlive probe داخل البيئة نفسها؛ نجاحه على Windows ليس اختبار Cloud.
7. من الموبايل افتح Codex واختر البيئة المنشورة واطلب المهمة. محادثة Cloud جديدة لا ترث نص محادثة Windows؛ تستعيد السياق العام من هذه الملفات وسياق الزبون من API. أكمل نفس مهمة Cloud إذا أردت الاحتفاظ بتفاصيل العمل الجاري.

راجع [توثيق OpenAI الرسمي لبيئات Cloud](https://learn.chatgpt.com/docs/environments/cloud-environments) للإعداد الحالي. الإرشادات أعلاه تخص Cloud الحالي؛ لا تفترض أن أسرار Legacy الخاصة بمرحلة التثبيت تبقى متاحة أثناء عمل الوكيل.

آخر تحقق شامل قبل حزمة Cloud: **1751 اختباراً** ناجحاً و**5 حالات متصفح** لاتصالات القراءة. سبقته حزمة #22 بنتيجة 1739 اختباراً و18 حالة متصفح، و8 محادثات فعلية مصطنعة/22 رسالة عبر OpenRouter. اختبرت ثلاث صور زبائن محددة بموافقة صريحة وتعرفت على P008 الموجود في الكتالوج الحالي؛ هذه الموافقة ليست موافقة عامة على رفع صور أخرى. لا تثبت الاختبارات أن معدل الحجز التجاري ارتفع أو أن كل خطأ محتمل انتهى.
