# ملف متابعة التعديلات من الموبايل — 8 نوفمبر 2026

هذا مدخل الحزمة الأخيرة لـCodex Cloud في بيئة `inqaa` المرتبطة بمستودع `Ahmed-ALshmre/inqaa` وفرع `main`. تفاصيل المعمارية والصلاحيات ومتطلبات الرد والحجز في [ملف التسليم الرئيسي](../CLOUD_HANDOFF_AR.md)، و`AGENTS.md` يوجّه لقراءته تلقائياً.

## ما تتضمنه الحزمة

### مستشار Sol للحالات الصعبة

الموديل `openai/gpt-6.1-sol` مستشار داخلي مرة واحدة عند عجز الرد أو ضياع السياق أو قرار تحويل بسبب عجز البوت. يستلم النص والذاكرة والاختيارات والحقائق اللازمة، ويعيد توجيهاً للموديل الرئيسي المضبوط في المتجر ليصيغ الرد باللهجة العراقية.

إذا بقي الفشل تسجل مراجعة بشرية وتوقف المحادثة بصمت، مع الاحتفاظ بسلتها. طلب الموظف الصريح والإجراءات التي تحتاج موظفاً فعلياً تحافظ على مساراتها المباشرة. لا تُبدّل موديلات التوليد أو الصور/الصوت، ولا تفعّل تجربة Terra/Gemini بدلاً عنها.

الملفات: `account_app/reply_consultant.py`، ربطه في `call_main_ai` داخل `app.py`، وحدود النقل الاختيارية في `ai_transport.py`. سجل الاستهلاك بالغرض `reply_consultation`. المستشار40 ثانية وإعادة صياغة الرئيسي45 ثانية، واستشارة واحدة للحالة. `REPLY_CONSULTANT_ENABLED=0` يلغي الميزة للتراجع التشغيلي. [التفاصيل والاختبارات](2026-11-08-sol-reply-consultant.md).

### دايلوك الأسئلة وتعليم طريقة الإجابة

تظهر الأسئلة الناقصة عند فتح الرئيسية، مع اسم المتجر والمنتج،12 سؤالاً ثم تحميل إضافي. تكتب الموظفة شرحاً للمعلومة وكيف يتعامل البوت مع السؤال، لا نصاً ينسخ للزبونة. الحفظ لا يعيد قائمة المحادثات ولا يرسل أو يشغّل محادثة متوقفة. يحافظ فشل الحفظ على الكتابة، ويمنع تعارض تحديث موظفين.

أضيف `product_questions.guidance` مستقلاً عن `answer` القديم. التوجيه يقيد بالمتجر والمنتج والموضوع، والحالات الخاصة بنفس الزبون والسؤال. تبقى فحوص حقائق المنتج والتسعير والحجز فعالة. [التفاصيل والاختبارات](2026-11-08-question-guidance-dialog.md).

### تجربة البيع الموجودة في المستودع

`dual_sales.py` و`dual_sales_strategy.py` وأدوات المحاكاة توثّق التجربة السابقة لقيادة Terra وصياغة Gemini. هي معزولة عن مسار الإنتاج وغير مفعلة تلقائياً. وجودها فيGitHub لا يغيّر طلب المالك الأخير: الموديل الرئيسي يبقى المضبوط لكل متجر، وSol للاستشارة فقط. [خطة الأسلوب](2026-11-08-warm-sales-plan.md)، [حدود التجربة](2026-11-08-dual-sales-trial.md).

## التحقق من نسخة السيرفر

- الفرع التشغيلي: `main`؛ النشر مرتبط بـGitHub على Railway، بيئة `clever-purpose / production`.
- بصمة `account_app/app.py` لهذه الحزمة بعد توحيد نهايات الأسطر: `70a7bd5c1f30698a`.
- اقرأ `/health` ثم اتصال القراءة: `python -X utf8 tools/live_system.py manifest`. قارن `code_version` بالبصمة وبسجل GitHub Deployments؛ رفع فرع لا يثبت النشر.
- قُرئت المتاجر الخمسة في8 نوفمبر قبل النشر وكانت AI مفعلة جميعاً. هذه ملاحظة تحقق وليست أمراً بالتفعيل. اقرأ الحالة الحية مجدداً قبل أي تغيير.

## بدء تعديل جديد من الموبايل

اختر بيئة Cloud المنشورة `inqaa`. يمكن كتابة:

> حدّث نسخة المشروع من main مع الحفاظ على أي عمل غير محفوظ، واقرأ AGENTS.md وdocs/CLOUD_HANDOFF_AR.md وdocs/updates/2026-11-08-release.md. تحقق من بصمة النظام الحي واتصال القراءة، ثم نفّذ التعديل التالي على فرع codex/ واختبره بمعزل عن رسائل وطلبات الإنتاج: …

المحادثة المفتوحة سابقاً قد تحتفظ بنسخة قديمة. افحص `git status` و`git log` أولاً؛ لا تستخدم `reset --hard` أو تمسح عملها لتحديثها. في نسخة نظيفة استخدم `git fetch origin` ثم حدّث من `origin/main`. الشفرة والوثائق من GitHub، وبيانات النظام من اتصال القراءة فقط.

سر Cloud المسموح للقراءة `INQAA_LIVE_TOKEN` يبقى داخل البيئة. لا تنقل ملف DPAPI الخاص بـWindows ولا ترفع مفاتيح OpenRouter أو ملفات `outputs/` إلى GitHub. إذا كانت قراءة Windows داخل sandbox لا ترى المسار المعتاد، يمكن تحديد ملف الاتصال المحلي الموجود مسبقاً بـ`--profile`؛ لا تنشئ اتصالاً إدارياً لتجاوز اتصال منتهي أو ملغى.

## أوامر الفحص

```bash
python -X utf8 tools/check_cloud_handoff.py
python -X utf8 tools/check_cloud_handoff.py --live
python -X utf8 -m account_app.tests.run_isolated
node --test account_app/tests/test_pwa_install.cjs account_app/tests/test_dashboard_ai.cjs
python -X utf8 tools/check_question_guidance_ui.py
```

فحص المتصفح الأخير يستخدم Edge على Windows؛ Cloud/Linux يحتاج تكييف اختيار المتصفح إلى Chromium المتاح. لا تدّع تشغيل فحص لم ينفّذ. للمستشار ثلاثة اختبارات فعلية مصطنعة ناجحة عبر OpenRouter؛ بقية فحوص الربط محلية بمزود محاكى. لا تعِد تشغيل محادثات قديمة على الإنتاج أو تنشئ طلبات حقيقية لاختبار التعديل.

المراجع الرسمية لبيئة الموبايل وتحديث المستودعات: [OpenAI Docs — Cloud environments](https://learn.chatgpt.com/docs/environments/cloud-environments). لا يُنقل عمل محادثة محلية غير مرفوع تلقائياً إلى Cloud؛ لذلك يجب أن تصل التعديلات إلى GitHub أولاً.
