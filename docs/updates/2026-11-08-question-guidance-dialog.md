# دايلوك الأسئلة وتوجيه طريقة الرد — 8 نوفمبر 2026

طلب المالك: تظهر الأسئلة الناقصة عند فتح الصفحة الرئيسية إن وجدت، وتكون الإجابة شرحاً يفهّم البوت كيف يتعامل مع السؤال، لا رسالة تنسخ للزبون.

## الواجهة

- يفتح `/dashboard` دايلوكاً واحداً في الزيارة، بعد استعلام محدود بـ12 سؤالاً. العرض العام يشمل المتاجر، و`store_id` يقيّد العرض بالمتجر المحدد. اسم المتجر والمنتج ظاهر بجانب كل سؤال.
- زر تحميل المزيد يستخدم مؤشراً للصفحة التالية؛ الحفظ لا يعيد تحميل المحادثات أو بقية البطاقات. يمكن تأجيل النافذة، ولا يعيد التحديث الدوري فتحها. تعود الأسئلة المتبقية في الزيارة التالية.
- لا يفتح دايلوك فارغاً. ينتظر إذا كانت الموظفة تكتب أو توجد نافذة مفتوحة. دعوة تثبيت التطبيق لا تغطي الأسئلة على الموبايل.
- صفحة `/product-questions` تستخدم المحرر نفسه. يكتب الموظف المعلومة المؤكدة وطريقة الإجابة، مثل: «وضحي أن هذا المنتج ثقيل وشتوي، واسألي عن القياس إذا بعده مو معروف». الشرح يصل للموديل كتوجيه خاص بالسؤال؛ المطلوب صياغة عراقية تناسب سجل المحادثة.
- فشل الحفظ يبقي النص في الحقل. تحديث موظف آخر يرفض الكتابة فوقه برمز409. صلاحية الرد تسمح بتوجيه أسئلة المنتج؛ توجيه السعر يحتاج إدارة المنتجات، وحساب العرض لا يستلم المحرر.

## المعرفة والرد

عمود `product_questions.guidance` مستقل عن `answer` القديم. الترحيل لا يعيد تفسير الأجوبة السابقة ولا يغيّر السعر أو المواصفات. لا يُضاف الشرح إلى FAQ أو حقول المنتج، ولا يصبح جواباً حرفياً في `exact_answer`.

التوجيه يقيّد بالمتجر والمنتج والموضوع. آخر توجيه للموضوع هو الفعال. «تفصيل المنتج» يحتاج مطابقة السؤال المطبّع، وإرشاد متابعة طلب خاص يحتاج أيضاً نفس الزبون؛ لا تُعمّم تفاصيل شحنة فردية. عنوان المحل يشترك داخل المتجر فقط.

الأسئلة الموجّهة تمر إلى مولّد الرد مع السياق، بدل اختصارات الأجوبة الجاهزة. يتحقق النظام من عدم نسخ الشرح كاملاً: يعيد المحاولة عند النسخ، ثم يتوقف بصمت إذا تكرر. تبقى مراجعات السعر والمخزون والاختيارات والموافقة والحجز فعالة. إذا بقيت معلومة أخرى ناقصة في سؤال مركب تظل بحاجة إلى مراجعة؛ شرح الليكرا لا يحل نقص البطانة أو السعر.

حفظ التوجيه وحده لا يرسل رسالة، ولا يعيد تشغيل AI، ولا يغلق المراجعة البشرية، ولا ينشئ طلباً. نقص حقيقة لم يوضحها الشرح يبقى سبباً للتحويل الصامت؛ التوجيه ليس تصريحاً بالتخمين.

## التحقق

اختبارات الترحيل، فصل الشرح عن الحقائق، نطاق المتجر والمنتج والموضوع والمحادثة، سؤال مركب، صلاحية السعر وCSRF، التصفح المحدود، منع تداخل تحديثين، تمرير التوجيه الفعلي إلى برومبت المزود، ومنع نسخه للزبون موجودة في `account_app/tests/test_question_guidance_nov08.py`.

```powershell
python -X utf8 -m account_app.tests.run_isolated
python -X utf8 tools/check_question_guidance_ui.py
node --test account_app/tests/test_pwa_install.cjs account_app/tests/test_dashboard_ai.cjs
```

فحص Edge يستخدم قاعدة مؤقتة وطلبات Flask معزولة؛ لا يتصل بإنتاج ولا يرسل للزبائن أو يستدعي موديلات فعلية. لقطات الموبايل والكمبيوتر ونتائج الفحص في `outputs/question-guidance-nov08/`، خارج Git. حالة النشر تؤخذ من `main` وسجل GitHub Deployments وبصمة `/health`؛ اقرأ [ملف متابعة الإصدار من الموبايل](2026-11-08-release.md).

النتيجة النهائية: نجح1911 اختبار Python في329 ثانية، و11 حالة Edge على الكمبيوتر والموبايل بلا أخطاء JavaScript، و10 حالات تثبيت مع اختبار اقتراحات AI في Node. شملت اختبارات Python20 حالة جديدة لهذه الميزة، وفحص استلام webhook وبرومبت المزود محلياً بمزود محاكى؛ لم تُجرَ استدعاءات توليد مدفوعة لهذه الحزمة. كشفت الجولة الأولى3 حالات توافق بسبب إضافة قائمة توجيه فارغة لمنتج لا يملك توجيهاً؛ أُصلحت وأعيدت الجولة الشاملة بنجاح.
