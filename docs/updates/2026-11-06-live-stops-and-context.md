## أسباب التوقف المثبتة

- سجل المزود 629 استجابة HTTP 200 وست استجابات HTTP 402 في نافذة المراجعة. رفض الرصيد سبب تشغيلي مستقل؛ إعادة تشغيل AI أو ربط المنتج لا يشحن حساب OpenRouter. لا نبدّل النموذج أو المفتاح، ولا نكرر رفض الدفع تلقائياً.
- فشل إرسال ردين جاهزين على مسار الربط؛ عبارة `manychat_send_failed` كانت تظهر حتى لمتجر Zernio. أصبحت نتيجة الموظف تميّز خدمة التوليد عن حالة مزود الرسائل ورمز HTTP عندما يتوفر، دون نسخ أجسام المزود أو الأسرار.
- التحويل البشري المقصود بعد الحجز كان يمكن أن يُسجّل كفشل إرسال عند الربط. يُسجَّل الآن كتحويل مكتمل، ويظل فشل المزود الحقيقي فشلاً ظاهراً.
- بعض التحويلات صحيحة: معلومات إغلاق أو موسم أو قياسات غير موجودة، صورة غير محسومة، شكوى أو تعديل لطلب محفوظ، أو إيقاف الموظف للمحادثة. لم نملأ تلك الحقائق بالتخمين، ولم نُعد تشغيل المحادثات القديمة بالجملة.

في قراءة لاحقة أثناء العمل كانت آخر ثمانية طلبات للمزود HTTP 200؛ لذلك لا يصح وصف كل محادثة صامتة بأنها نقص رصيد مستمر. يبقى سجل 402 سبباً مثبتاً للحالات التي وقع فيها، وتُقرأ حالة المزود الحالية وقت إعادة المحاولة.

## الإصلاحات

1. حفظ «متوفر 40» و«40 متوفر» كقياس مفضّل دون اعتباره موافقة شراء. رُفع إصدار أدلة الذاكرة لإعادة بناء السياق المحفوظ من الرسائل.
2. تذكّر «رايدين قطعتين» و«رايده قطعتين» عند التسعير اللاحق، واستعمال الكمية في السعر مع التوصيل. السؤال عن المجموع لا ينشئ طلباً.
3. فهم «اشكد يطلع» كسؤال مجموع مختصر مع إبقاء أسئلة الطول والمقاس وأجور التوصيل مستقلة.
4. الإجابة المحلية عن حقائق المنتج المعروفة، بما فيها أعمار البكج والقماش والطول معاً، بعد إتاحة مسار إكمال الحجز الصحيح أولاً. الأسئلة التي تتطلب تفسير الملاءمة أو معلومات ناقصة تحتفظ بمسارها الكامل.
5. عدم استبدال «أخاف قياس 40 يطلع جبير» أو مقارنة L مع 44 بعبارة «قياسج موجود»؛ التوفر والملاءمة مختلفان.
6. سؤال «إذا أطلب شوكت يوصل؟» ليس وعداً مشروطاً بوصول مضمون؛ تبقى شروط مثل «بشرط يوصل باجر» حاجزاً حقيقياً أمام الحجز.
7. سؤال استكشاف مثل «لا فساتين أكثر قياس 40» لا ينشئ طلب تغيير لقياس الحجز السابق، مع بقاء التصحيح الصريح للطلب مسجلاً للمراجعة.
8. سؤال عن قمصان أو وشاحات غير موجودة في كتالوج المتجر لا يؤكد توفر التنورة السابقة، ولا يعيد صورها أو يحجزها.
9. سبب فشل إعادة التشغيل يصل إلى الموظف: نقص الرصيد، فشل مزود الرسائل، أو حقائق محددة ناقصة؛ لا يُرسل تشخيص تقني للزبون.
10. عند طلب قطعتين بلونين وقياس واحد معروف، تُحفظ قطعة من كل لون مع وصول بيانات التواصل دون سؤال موافقة ثانٍ. لا يُخمن توزيع أربع قطع على لونين، ولا تُوحّد قياسات طفلين أو منتجين مختلفين. يبقى سؤال السعر استفساراً دون إنشاء طلب.
