# ربط حجوزات صوف ومنج

يُسجّل صوف الحجز عبر واجهة منج الموثقة، ثم يرسل إشعاراً مقروءاً إلى كروب المتجر. لا يعتمد التسجيل على قراءة بوت لرسالة بوت آخر؛ Telegram يمنع ذلك.

- يحفظ منج معرّف الحجز المصدر والمتجر والمحادثة والمنتجات واللون والقياس والعدد والسعر والتوصيل.
- إعادة الطلب بنفس المصدر والمعرّف والمتجر تعيد الحجز نفسه، ولا تكرر التسجيل.
- تعاد محاولة مهلة HTTP 408 وضغط HTTP 429 وأخطاء الخادم مع الحمولة والهوية نفسيهما؛ يراعى `Retry-After` ضمن تأخير محدود بساعة. لا تعاد إرسال الطلبات المقبولة.
- ينسب الحجز إلى AI أو الموظف بحسب مسار تثبيته، وليس اسم الموظف المكتوب في الرسالة.
- يراجع صوف حالة الحجوزات المرتبطة دورياً. الإلغاء والنواقص والمسودات لا تدخل في عدد الحجوزات المؤكدة.
- بعد تفعيل الاتصال، تعتمد نسبة صوف على زبائن المحادثات الذين لديهم حجز مسجل في منج. تبقى أعداد الحجوزات المحلية منفصلة. نسبة الطلبات إلى مراسلات الإعلانات في منج لها مقام مختلف.
- تُحجز الطلبات القديمة غير المرسلة للمراجعة، ثم تُربط فقط عند وجود طلب واحد مطابق في منج في المتجر واليوم والهاتف والعنوان والمنتجات والمبلغ. لا تنشئ المطابقة طلباً جديداً ولا ترسل رسالة، ولا تنسب الطلب القديم تلقائياً إلى AI.

## التفعيل

1. احفظ مفتاحاً عشوائياً قوياً في منج: إعدادات المدير الذكي، ربط الطلبات.
2. احفظ المفتاح نفسه في إعدادات ربط منج في صوف، مع العنوان `https://web-production-b168b0.up.railway.app/api/v1/orders`.
3. زامن المتاجر وراجع كل مطابقة. لا تربط متجراً بمتجر آخر لمجرد تشابه الاسم.

المفتاح يمنح صلاحية إدخال الطلبات وقراءة حالات الحجوزات ومعرّفات المتاجر؛ لا يوضع في Git أو رسائل Telegram أو رابط URL. يمكن إبقاء مفتاح بيئة منج السابق فعالاً للتوافق، مع مفتاح الربط المحفوظ من المدير.

## التحقق المعزول

`python tools/verify_menger_roundtrip.py --menger-repo PATH`

يستخدم قواعد بيانات مؤقتة ويمنع الشبكة الحقيقية. يفحص التسجيل والتفاصيل والإلغاء والمطابقة التاريخية ومنع التكرار. هذا الاختبار لا ينشئ حجوزات إنتاجية.
